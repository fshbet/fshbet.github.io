§05

How this archive is measured

counted from source

Every number on this page comes out of the repositories themselves. None of it is estimated, rounded up, or carried over from memory. This is the whole pipeline.

  1. 01

    Source

    Start from the working tree of each repository — the files actually authored, in the state they are in.

  2. 02

    Filter

    Drop dependencies, virtual environments, lockfiles, generated API schemas, minified bundles and build output.

  3. 03

    Measure

    Count tokens with tiktoken cl100k_base — the same encoding a language model reads the code through.

  4. 04

    Classify

    Separate code, tests, documentation and configuration, so each project's real ratio stays visible.

  5. 05

    Publish

    Print the figures as counted, alongside the gaps each repository records about itself.

What a token is
Tokens are counted with tiktoken cl100k_base across source, test, documentation and configuration files — the same encoding a language model would read them through. It is a measure of how much there is to read, not a measure of quality.
What is excluded
Dependencies, virtual environments, lockfiles, generated API schemas, minified bundles and build output are excluded from every count. What remains is authored code. For the CAD project that means the exported STL meshes are excluded — they are build output of the OpenSCAD source, which is what gets counted.
Why the split
Tests and documentation are reported separately from implementation, so each project's real ratio stays visible instead of being averaged away. Documentation share per repository on this page is derived from those same counts.
Where the gaps come from
Most repositories carry an INDEX.md written from their own source — architecture, usage, layout, and an explicit section naming what is missing. Four carry their own documentation set instead: SBC, Sentinel (29 topic guides and 12 architecture decision records), the CAD project, whose docs/design-notes.md holds the measurement table, the coordinate transform and the validation record, and the data-intelligence platform, which ships an architecture reference, an operator guide and a self-contained how-it-works.html.
One card reads differently
The enclosure has no test suite, so its third metric counts printed parts rather than test files. Everything else on this page is software.
On status
Ready means documented end to end, tested, and running. Gaps noted means functional and worth reading, but not finished — and the gap is printed on the card rather than left for you to find. Not public means there is no repository link to give; it does not mean the work does not exist.
